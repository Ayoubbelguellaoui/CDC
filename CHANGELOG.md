**Changelog**
All notable changes to OpenCDC will be documented in this file.

**[Unreleased]**

**Changed**
- **Version bump to 1.0.0**: tool version string (`--version`, report header, SARIF, docs) aligned to 1.0.0.

**Fixed**
- **Yosys sync-reset-with-enable flops were unmapped**: `$_SDFFE_*`, `$_SDFFCE_*` (and the related `$_DFFSR_*`/`$_SDFFSR_*`/`$_DFFS_*`/`$_DFFR_*`/`$_ALDFF_*`/`$_ALDFFE_*` families) fell through to `Unknown`, were modeled as opaque combinational, and the flops — plus every crossing through them — silently vanished from the analysis while the summary still reported `status complete`. The built-in classifier now recognizes these families as sequential. Netlists that use them no longer emit the `unmapped cell type(s)` warning and keep their registers in the graph.
- **Unknown sequential-like cells no longer produce a false "complete"**: when the netlist frontend meets an unmapped cell whose name looks sequential (DFF/LATCH/FF/REG…), it flags the run; `analysis_status` becomes `incomplete` and `--signoff` reports `INCOMPLETE — Analysis incomplete — unknown sequential cells not modeled` instead of a clean complete/PASS. New fixture `unknown_sequential_cell.v` + regression test; new `yosys_sdffe.v` fixture asserts `$_SDFFE_PP0P_`/`$_SDFFCE_PN0P_` classify and appear as registers.

- **README honesty pass**: lead with static-vs-formal scope, a verified-vs-guessed table, measured known limitations (from `benchmarks/expected/manifest.json` `known_gaps`), and a real terminal screenshot. CDC005/CDC013 called out as optional methodology checks. Features list moved below usage. `.commandcode/` added to `.gitignore`.
- **Professional text report redesign**: the text report is now sectioned and review-friendly — an `OpenCDC vX.Y.Z — CDC static analysis` header (top module, input type, input files), a `Findings` section with severity-grouped (ERROR → WARNING → INFO) numbered entries that show uppercase severity labels, rule ids **and rule names**, crossings, reasons, `file:line:col` locations and status tags, a human `Summary` block (status/findings/waived/suppressed/mc_suppressed), and a `Signoff` section under `--signoff`. The machine-readable `analysis_status=...` line still goes to stderr unchanged.
- **ANSI colorization + `--color auto|always|never`**: text reports colorize severity (red/yellow/blue), section headers (cyan), signoff verdicts (green/red) and dim metadata. `auto` enables color only on a TTY, never into `--out` files, and honors `NO_COLOR`.
- **JSON CLI output includes `coverage` and `signoff`**: the CLI now emits the full JSON envelope (the previously unwired reporter overload); keys are additive, existing consumers are unaffected.
- **Terminal screenshots regenerated** (`docs/images/opencdc_*_terminal_report.png`) from real colored runs of the redesigned report.

**Fixed**
- **Logic in front of a packed synchronizer passed as a chain (false negative)**: `packed_shift_chain_stages` verified the shift structure of `s <= {s[0], tail}` but accepted any tail, so `{s[0], a & e}` - logic of two source registers that can glitch into the synchronizer - was a verified 2FF. A scalar chain already failed in this case (its first stage has no direct cross-domain register predecessor). The tail must now be a signal or a select of one; otherwise the vector is no chain and the crossing is CDC001 error. New fixture cases + `LogicInFrontOfPackedSynchronizerIsNoChain` (fails before) and the guard `SelectIngressOfPackedSynchronizerIsAChain`; 606/606 ctest, corpus 25/25 F1 1.000.
- **`report_double_synchronization` policy (opt-in): a source synchronized twice that reconverges is CDC003**: by default `check_pairs` skips a single-bit source whose two crossings both have synchronizer chains. Two independent synchronizers of one signal are a reconvergence hazard: each may resolve the same transition in a different cycle, so the copies disagree for a cycle where they meet. With `report_double_synchronization: true` (config; set by the `strict` and `asic_signoff` profiles) such a pair is CDC003, with the reason "synchronized twice ... Synchronize once and fan out". The default is unchanged; each setting has a test.
- **CDC003 for correlated sources and at output ports**: two different sources of one clock where one derives from the other (a delayed copy, `a_one <= a_r`), each synchronized on its own, lose their relation where they meet - not seen, as CDC003 required one common source register. `check_correlated` reports such pairs (the derivation within `max_hops` registers of the source clock, `derives_from`); unrelated sources are not reported. Meeting points now include top-level output ports reached through nets and logic (`meeting_points`), not only registers. New fixture cases + `SourceSynchronizedTwiceReconverges`, `CorrelatedSourcesReconvergeAtAPort` (fail before) and the guards `SourceSynchronizedOnceDoesNotReconverge`, `IndependentSourcesDoNotReconverge`; 604/604 ctest, corpus 25/25 F1 1.000.
- **CDC009 for a reset synchronized in the wrong clock domain**: a reset synchronized in one clock domain and used as the asynchronous reset of another clock's registers releases them asynchronously to their clock - a classic RDC bug no check covered (CDC009 compares the resets of registers on a data path only). `ResetDomainAnalyzer::check_reset_crossings` reports each register whose asynchronous reset traces (`SlangAdapter::resolve_resets`) to a register of another clock domain: CDC009 error, source the synchronizer output, "its release is not synchronized to the register's clock". Not tied to `check_same_clock_reset_crossings`. New `rh_wrong_domain` / `rh_right_domain` fixture cases + `ResetSynchronizedInAnotherClockDomainIsFlagged` (fails before) and the guard `ResetSynchronizedInItsOwnClockDomainIsClean`; 600/600 ctest, corpus 25/25 F1 1.000.
- **Assignments to a concatenation were dropped (false negatives)**: `extract_lvalue` names no concatenation, so `{a, b} <= ...` in a procedural block and `assign {c, s} = ...` produced no node and no edge - the registers did not exist. A 2FF synchronizer written `{s1, s0} <= {s0, a_r}` (a common reset-synchronizer form) was invisible, and so was any crossing into or out of such registers. `split_concat_assignment` flattens the left-hand side and gives each element its right-hand side: the matching element of a same-shaped right-hand side concatenation (so the shift form is a chain), else the whole right-hand side; each is a direct dependency, conditions included. New `concat_lhs.sv` fixture + `ConcatenationShiftIsASynchronizer`, `ConcatenationLoadedRegistersCross`, `ContinuousConcatenationAssignFeedsTheCrossing` (all fail before); 598/598 ctest, corpus 25/25 F1 1.000.
- **A divided clock split its root into two domains (false CDC001)**: a register clocked by a dividing register (`div <= ~div` on clk_a) traced to the divider, whose root clock was not resolved yet, and took the divider's raw clock name (`top.clk_a`) for a root next to `clk_a` - the same clock as two domains, a false crossing between them. `trace_to_top_level_source` now traces a dividing register's own clock to its source (bounded depth for dividers of dividers), so divided clocks fold into their root as documented.
- **`muxed_clock_domain` policy (opt-in): a mux of two clocks as a clock domain of its own**: by default a muxed clock is represented by one input (the default path), so a register on `sel ? clk_b : clk_a` fed from clk_a is in clk_a's domain and its crossing for `sel = 1` is not reported. With `muxed_clock_domain: true` (config; set by the `strict` and `asic_signoff` profiles) a mux whose values (not its select) trace to two or more different roots is a clock domain of its own, named by its output (`ClockResolver::trace_clock_mux`; the RTL frontend records the select operands, `Node::mux_select_inputs`), so a register on it crosses from both clocks (CDC001, and CDC005 without reset); honored by the RTL and netlist frontends and the relationship pass. A mux of one root (a clock and its divided copy) is unchanged. The default is unchanged, so the RTL/netlist parity holds; each setting has a test (RTL and netlist).
- **Correct handshakes got a stage-fanout warning (regression of the first-stage tap check)**: the stricter stage-fanout check (any register reached through nets, ports, logic or conditions) ran on every stage before the last. A register copying the synchronized value - a handshake ack, an edge detector's delay - looks like one more stage, so the real last stage, also used as a condition (`if (req_s1 && !ack) data <= ...`), got a warning on a correct req/ack handshake and on a data-enable synchronizer. The strict check now applies to the first stage, the one that can be metastable; a later stage warns, as before, only on a second same-domain *data* successor (a deliberate 3-stage chain tapped after stage 2 - `SyncAdversarialTest.FanoutOnStage2TriggersWarning`). New `cd_stage2_condition` fixture case + `SecondStageUsedAsConditionIsNoFanout` (fails before the fix); 593/593 ctest.
- **Crossings through an if/case condition were invisible (false negatives)**: `collect_assigns` recursed into the branches of an if or case but dropped the condition, so a signal that gates an assignment - an asynchronous flag used as an enable, `if (a_r) q <= 1'b1;` - had no edge to the register. The signals of every enclosing condition (the block's own asynchronous reset excepted: the reset-domain check) are now inputs of the assignments inside, as `EdgeRole::Control` edges beside the data path (merged into it, an enable would hide a synchronizer behind logic). `Graph` keeps the role per edge (`edge_role`); `register_successors`/`register_predecessors` take `data_only`, which the synchronizer matcher and CDC006 use, so a register gated by a synchronized value is no further stage and a chain with an enable stays a chain. On the SerDes this exposed a real design bug: the TX FIFO read data is gated combinationally by a comparison against the write pointer (`data_rd = ~err_wr_rd ? mem[addr_rd] : 0`, `err_wr_rd = addr_wr == addr_rd`), captured unsynchronized in the read domain. Stress fixture +8 (the enable crossing `u_reconvergence.consumer_valid_r` -> `u_handshake`, 3 CDC001, 3 CDC003, 2 CDC008); `corpus_fifo_binary` gains CDC013 (its writes are gated by a full flag from the unsynchronized read pointer), removed from its absent rules.
- **A synchronizer read at its first stage passed as verified**: the stage-fanout check counted only registers reached through nets, so the still-metastable first stage read through logic, or by an output port, gave CDC001 info. A stage before the last must feed the next stage only: any other register reached through nets, ports or logic, or a top-level output, is a structural warning (CDC001 warning). New `control_dep.sv` fixture + `CrossingThroughAnEnable`, `FirstStageReadThroughLogicIsFlagged`, `FirstStageReadByOutputPortIsFlagged` (fail before) and the guards `EnabledSynchronizerIsStillAChain`, `ConditionGatedConsumerIsNoStage`; 592/592 ctest, corpus 25/25 F1 1.000.
- **Reset domains were keyed by the reset's port name (false and missed CDC009)**: a register's reset was the bare name of its event signal in its own module, never traced through the hierarchy as clocks are. One reset net entering two modules as `i_reset_n` and `rst_n` became two reset domains (on the SerDes, 14 false CDC009 errors from its 8b10b decoder into the RX framer and FIFO), and two different resets entering two modules both as `rst_n` - the top reset and its synchronized copy - became one, hiding a real reset-domain crossing. `SlangAdapter::resolve_resets` traces each register's reset from its path in the register's module back through single-driver nets and ports to the source: a top-level port keeps its port name (unchanged results for flat designs), a register (a reset synchronizer), logic (a combined reset) or an undriven port is named by its path. New `reset_hier.sv` fixture + `ResetRenamedByPortIsOneResetDomain`, `TwoResetsBehindOnePortNameCross` (both fail before the fix); 587/587 ctest, corpus 25/25 F1 1.000.
- **A clock from a black box split into one domain per port**: a clock whose source is an undriven instance output (a PLL/MMCM model) had no top-level root, so each submodule clock port it reached became a domain of its own (`clk_wr`, `clk_rd`, `clk`, ...). `trace_through_hierarchy` takes an undriven instance output port as a clock source, named by its hierarchical path, and `SlangAdapter::resolve_clocks` keeps such a root instead of re-tracing it. The SerDes: 3 domains (2 MMCM outputs, the RX clock) instead of 7.
- **Synchronizers shifted by a procedural for loop were not chains**: `for (int i = 1; i < N; i++) s[i] <= s[i-1];` indexes by a loop variable, so `s` stayed one node and every such synchronizer reported CDC001 error. Procedural for loops with static bounds (one variable, `< <= > >= !=`, `++ -- += -=`, at most 1024 iterations) are unrolled (`unroll_for`); the loop variable is a static index in each iteration, for the array split and the assignments.
- **Gray pointers were not recognized as gray**: a gray tag was set only in procedural blocks, never by a continuous assign (`assign g = b2g(b);`), never carried through a pure capture (`g_r <= g;`), and a function building the code bit by bit (`g[i] = b[i+1] ^ b[i]`, `g[W-1] = b[W-1]`) was no gray encoder. All three are recognized (continuous-assign check, `propagate_gray_captures`, `bitwise_gray_formal`).
- **Wide gray synchronizer chains were errors**: the matcher classified only one-bit chains, so every correct async FIFO reported CDC001 error on its pointers (a known gap). A gray-coded source reaching the chain through nets and ports only may use stages as wide as the destination (`gray_source`); a binary bus through the same chain stays an error.
- **A gray register decoded before it crosses suppressed CDC002**: the recognizer took any gray-coded source register for a safe gray crossing whatever lay on the path. The gray cases of `is_verified_safe_crossing` (and the wide-chain rule) now require a wire-only path (`wire_path`); logic between the registers - a gray-to-binary decoder in the source domain - makes the crossing a plain multi-bit one (the stress fixture's `u_gray_counter.count_out` keeps its CDC002). The SerDes now reports every documented crossing as verified (5 pulse synchronizers, 2 level synchronizers, the 4 gray-pointer crossings of both FIFOs: CDC001 info) and one error, the TX FIFO memory read in the read domain (the payload a FIFO protects by its pointers; protocol verification is out of scope - a waiver). Benchmark manifest: the async gray FIFO controls are now `info`, the wide-chain gap is narrowed to non-gray buses; README updated. New `fifo_sync.sv` fixture + `LoopShiftedArraySynchronizerIsAChain`, `BitwiseGrayPointerSynchronizedByWideChain`, `GrayDecodedBeforeCrossingIsMultiBit`, `BinaryPointerThroughWideChainIsUnsafe`, `BlackBoxPllOutputsAreClockSources` (all fail before); the regression helper `analyze_fixture` runs the pattern recognizer like the CLI; 585/585 ctest, corpus 25/25 F1 1.000.
- **Signals leaving an instance were dropped (hierarchical false negatives)**: slang represents an output port connection as the Assignment `parent = <port>`, and the port-connection code collected operands of it, which finds nothing - so no edge left any child instance through an output port. A register in one child driving a register of another clock in a sibling or the parent was invisible (the README's "Hierarchical FN"; the corpus control `hierarchical_soc` was recorded as a known gap). The connection now takes the assignment's lvalue (`collect_actual_values`, already used for task outputs). The stress fixture gains the 7 inter-instance CDC001 crossings its own comments describe (e.g. `u_uart_rx.rx_data -> u_sync_2ff_bus.src_reg`, clk_uart -> clk_bridge) and their CDC002/004/005/007/008 companions (35 -> 61 findings); `GrayCounterSuppressed` now scopes to the gray crossing inside `u_gray_counter`, whose `count_out` is a decoded binary bus (a real CDC002). The `hierarchical_soc` ambiguous control (it named a wire, not a register) becomes a positive control `u_sender.status_ff -> u_consumer.q_raw_ff`; the gap leaves `known_gaps`.
- **The output of a clock-gate instance became a root clock**: with output ports connected, the clock resolver met the gate's `clk_o` port and took it for a root (every port counts as a clock port), so Ibex split into `clk_i` and `clk_o` with 21921 false findings. `ClockResolver::trace_through_hierarchy` walks a clock's drivers back through nets, instance ports and gating/muxing logic (not registers) to the top-level ports; of several (clock and enable of a gate), the one that clocks registers directly is the source. Only clocks that leave an instance through an output port are decided there; others keep the existing tracing.
- **Register path search was exponential**: `find_register_paths` enumerated every simple path, though both consumers keep the first path per destination, so a CPU core hit the 10000-path limit from one register (CDC010, analysis incomplete). The search is breadth-first, expands each node once and records each destination once - linear in the graph, shortest paths - and CDC010 names the limit hit (path count or depth). Ibex (`ibex_top`, one clock) is now complete: 120 registers in `clk_i`, 0 findings, 1.7 s. New `output_port.sv` fixture + `OutputPortReachesParent`, `ClockGateInstanceKeepsRootClock`, `PathSearchIsLinearInDiamonds` (all fail before the fix); 580/580 ctest; benchmark corpus 25/25, TP 46, F1 1.000.
- **Unpacked arrays failed elaboration (zero width) or hid synchronizers**: slang's `getBitWidth()` is zero for every non-numeric type, so ports, nets and registers of unpacked arrays (`logic [31:0] rf [32]`) became zero-width nodes and graph validation rejected the design (`Node '...' has zero width`) - the Ibex core could not be analyzed at all. Widths now come from `type_width()`: the bit width, else `$bits`, else 1 for types without a static size. In addition, an unpacked array whose every access is an element select with a static index (literal, parameter or genvar, `+ - *` of those) becomes one node per element (`s[0]`, `s[1]`), found by a pre-pass over the design (`ArrayAccessScan`); a synchronizer written as an array (`s[0] <= a; s[1] <= s[0];`) is now a chain (CDC001 info/TwoFF instead of error). An array read whole, through a port or with a variable index (`rf[sel]`) stays one node, so no connection is lost. Ibex (`ibex_top`) now elaborates: 120 registers, 2099 bits (1953 flip-flops after synthesis). New `unpacked_array.sv` fixture + `UnpackedArrayPortsHaveWidth`, `UnpackedArraySynchronizerIsAChain`, `UnpackedArrayWithVariableIndexStaysOneNode` (the first two fail before the fix).
- **Parameters, genvars and enum values became signal nodes**: operand collection named every referenced symbol, so `d & MASK` or the genvar in `w[i]` created an undriven net and an edge per use (500 of 2892 edges on Ibex, `g[k].i -> w` edges on a generate-loop filter). They are constants of the elaboration and are skipped. New `ParameterIsNoSignal` test (fails before the fix); 577/577 ctest.
- **Generate blocks merged loop iterations and split the module's signals (false negatives)**: the RTL frontend named every entry of a generate loop `g.` + its name, which is empty for loop entries, so all iterations collapsed into one node (`top.g..x`), and it named every signal a generate block reads after the block (`top.g.clk` for the module's `clk`), so module signals read inside a generate block - instance port connections and clock events included - became separate, unconnected nodes and a fake clock domain per instance clock port. Signals are now named after the scope that declares them (`SlangAdapter::scope_paths_`, consulted for named values, lvalues and clock events; resets keep their bare names), and loop entries are `g[0]`, `g[1]`, .... On a real filter design (generate loops of flip-flop instances) the graph went from 5 registers in 2 domains to 74 registers (585 bits, the flip-flop count of its synthesized netlist) in its single clock domain. Designs without generate blocks are unchanged (golden corpus byte-identical). New `generate_scope.sv` fixture + `GenerateLoopIterationsAreSeparateCopies` regression test (fails before the fix); 573/573 ctest.
- **CDC004 crash on intermediate gated clocks**: a gated register in the middle of a crossing path set `gated_hit` but the reason string still assumed the gated node was src or dst, null-dereferencing. The reason now names `gated_hit`.
- **`--profile` / `min_sync_stages` / `reconvergence_depth` were no-ops**: `apply_profile()` never ran in the analysis path, `CrossingAnalyzer::min_sync_stages_` was stored unused, and reconvergence BFS was hardcoded to 3 hops. Profiles and YAML knobs now take effect (a 2FF under `asic_signoff` stays CDC001 error).
- **Config `clock_groups.asynchronous` silently became exclusive false paths**: YAML `asynchronous: true` was ignored and every group defaulted to exclusive, hiding real async CDC. Async groups no longer expand into false paths.
- **CDC008 DFS leaked `on_path` on backtrack**, so a later 3-domain route through a shared join could be skipped. Sync chains with reset/fanout warnings are no longer marked `VerifiedSafe`. SDC `-from/-to [get_cells]/[get_pins]` false paths now match register hierarchical names.
- **CDC001 false positive for packed-vector 2FF synchronizers**: a synchronizer written as one packed vector with a concatenation shift assignment (`sync <= {sync[0], src}`) is now recognized exactly like the equivalent two-register form — downgraded to `info`/`verified_safe` with provenance "synchronizer chain detected at destination" instead of raising an `error`. The IR flattens such an assignment to a self-loop plus the cross-domain edge, indistinguishable from `sync <= sync | src` at graph level, so the fix verifies the exact shift structure on the slang AST (every upper operand must be the destination range below its own target position shifted up by the ingress width — `floor(width / ingress_width)` stages, so `{s[W-2:0], src}` classifies as 2FF/3FF/N-stage for any width) and tags the node (`ir::Node::packed_shift_depth`, set only by the RTL frontend); the `SynchronizerMatcher` consumes the tag in `find_pattern_for_dest`, `match` and `chain_depth`. Shapes that cannot be verified as pure shifts — reversed concatenations (`{src, sync[0]}`: the low bit only holds, there is no chain), right-shift chains, non-literal select bounds, multi-operand RHS — are conservatively still reported as unsynchronized, so no false negatives were introduced. New `packed_sync.sv` fixture + `PackedShiftChainTaggedOnAst`, `PackedSync2ffNoError` regression tests and six matcher unit tests; 560/560 ctest and 13/13 strict RTL/netlist parity pass.
- **Muxed-clock root selection on netlists**: a clock-mux cell's inputs are now normalized to the shared IR operand order `[select, true, false]` (yosys `$_MUX_` A/B/S and library D0/D1, I0/I1, S pin roles are mapped), matching the RTL frontend's ternary operand order. Previously the resolver picked the last connection — the **select** pin — as the representative root clock, so a synthesized `sel ? clk_a : clk_b` mux reported a bogus `clk_a → clk_sel` domain pair instead of `clk_a → clk_b`. RTL behavior and golden outputs are unchanged (the shared `ClockResolver` is untouched); the parity harness now passes `--strict-counts` on `muxed_crossing` (13/13 strict designs pass). New `mux_clock.v` fixture + `MuxedClockResolvesToDefaultPathRoot` test.

**Added**
- **Low-power cell classification** (netlist plan PR15): isolation and retention cells are first-class citizens instead of `Unknown` opaque cells. New `CellKind::Isolation`/`CellKind::Retention` with default globs `*ISO*` (isolation clamps) and `*RSDFF*`/`*RETENTION*` (retention save/restore flops), Liberty import of the `is_isolation_cell : true;` power-aware annotation plus retention name heuristics on `ff` cells, and YAML cell-map kinds `isolation`/`retention`. Semantics: isolation cells are transparent combinational (Buffer-equivalent) and CDC001 crossings whose path crosses one are **downgraded to `info`/`verified_safe` with provenance "Path through low-power isolation cell"** — a methodology-managed power-domain boundary (UPF out of scope) is acknowledged without pretending it synchronizes: CDC002/004/005/007 stay fully evaluated on the same crossing. The netlist adapter flags isolation nodes (`ir::Node::is_isolation_cell`; RTL never sets it, so RTL runs are structurally unaffected), bus regrouping includes the flag in its grouping key and preserves it on merged cells, and an analyzer pass consumes it. Retention flops are modeled as plain registers (only CK/D/Q and reset/set bind; scan/save ports `SI`/`SE` are ignored), so the real sequential elements — and therefore the crossings they participate in — are never hidden by Unknown-cell opacity. New `low_power.v` fixture + `LowPowerIsolationDowngradesCdc001Only` integration test (retention bus regroups to width 2, CDC001 info/verified_safe, CDC002 stays error, no unmapped-cell warning) and unit tests for globs, YAML kinds, and Liberty annotations; 552 tests pass and the 13-design strict parity corpus still passes.
- **Hierarchical netlist elaboration** (netlist plan PR14): multi-module gate-level netlists are now analyzed instead of erroring out. `src/frontend/netlist/flatten.{h,cpp}` flattens the hierarchy into one module before graph building — child contents get `inst.`-prefixed names (a flop `ff0` inside instance `u_src` becomes the register `u_src.ff0`), child ports bind through the parent-side pin connections (named or positional, mapped in child port declaration order), names not bound upward keep their prefixed form, and sub-module definitions shadow library cells of the same name. Instantiation cycles — including indirect cycles back through the top module — are rejected with a clear `recursive module instantiation` error, and nesting deeper than 64 levels is an error. Flat netlists (the synthesized common case) skip the pass entirely. The parser now retains all module definitions in `ParseResult::modules`. Two new fixtures/tests (`hier_crossing.v` positional+named instances across two clocks, `hier_recursive.v` mutual recursion); 548 tests pass and the 13-design strict parity corpus still passes (flat path unchanged).
- **LSP netlist diagnostics** (netlist plan PR13): the language server now handles gate-level documents end to end — `opencdc lsp --input-type auto|rtl|netlist` forces the frontend when content detection misreads a document, parse errors are positioned at their source line/column parsed from the `file:line:col` prefix both frontends emit (previously everything collapsed to line 0), analyzer warnings (unmapped netlist cells, muxed-clock annotation requests) publish as `analysis-warning` diagnostics, and netlist findings anchor at their instance lines. Three new `LspTest` cases cover netlist analysis, forced input type, and error line mapping; docs updated.
- **Python bindings parity + CI coverage** (netlist plan PR12): `CheckOptions` exposes `input_type`, `input_type_explicit`, `cell_map_path`, `liberty_path`, `name_map_path`, and `max_nodes`/`max_edges`; `CMakeLists.txt` sets `POSITION_INDEPENDENT_CODE` globally so the fetched static deps (slang) link into the `opencdc` module; CI's build job configures with `BUILD_PYTHON_BINDINGS=ON` and runs a Python smoke test (import, set netlist options, end-to-end `run()` on a netlist fixture expecting exit 1).
- **CI parity job**: `.github/workflows/ci.yml` gains a `netlist-parity` job that installs yosys, runs the netlist frontend test suites, and executes `benchmarks/scripts/synth_netlist.py --strict-counts` on the 13-design strict corpus — RTL↔netlist parity regressions now fail CI instead of depending on manual harness runs.
- **RTL→netlist register name map** (netlist plan PR10): `--name-map <file>` CLI flag + `input.name_map` config key. The map (`rtl_name netlist_name` per line, `#` comments) renames netlist registers to their RTL names right after graph build and before gray recovery/bus regrouping, so bit groups merge under the RTL name and findings report RTL names at RTL granularity — RTL-authored waivers keep matching synthesized runs. Renames are skipped with a warning when a target name is already taken, and unmatched entries surface as stale-map warnings. New `name_map.{h,cpp}`, fixture pair (`namemap_crossing.v`/`.map`), and test; 543 tests pass.
- **Liberty (`.lib`) cell import** (netlist plan PR9): `src/cell/liberty.{h,cpp}` parses the classification subset of Synopsys Liberty libraries — `cell`/`pin`/`ff`/`latch` groups with `direction`/`clock`/`function`/`clocked_on`/`next_state`/`clear`/`preset`/`enable`/`data_in` attributes — and generates `CellDef`s automatically (flops with active-low/async clear inference from the expression, latches, and combinational cells with a logic-type hint derived from the output `function` expression; timing/leakage groups and vendor noise are skipped).
